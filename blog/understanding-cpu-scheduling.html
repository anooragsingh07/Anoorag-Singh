Understanding CPU Scheduling: FCFS, SJF, RR, and Priority

May 15, 2024 · 7 min read

CPU scheduling determines which ready process uses the processor next. Here is a plain-language look at four common ways to make that choice.

Several processes may be ready to run at the same time, while a processor can execute only one at a time on a single core. The operating system’s scheduler chooses what runs next. The choice affects waiting, completion time, and how processor time is shared.

First-Come, First-Served

FCFS serves processes in the order they arrive. It is easy to understand and implement because the ready queue behaves like a line. Its simplicity has a trade-off: if a long process reaches the front first, shorter jobs behind it wait even if they could finish quickly.

Shortest Job First

SJF chooses the process with the shortest expected CPU burst. When the burst estimates are accurate, short tasks can complete with less waiting. The scheduler must know or estimate the next burst, and longer work may wait when short jobs keep arriving. A preemptive variation can switch to a newly arrived process with a shorter remaining time.

Round-Robin

Round-Robin gives each ready process a fixed time slice, then moves to the next process if work remains. This rotation shares the processor regularly. The time quantum matters: a very small quantum causes more context switches, while a large quantum makes the method behave more like FCFS.

Priority Scheduling

Priority Scheduling selects a process according to its assigned priority. It can favor urgent or important work, but low-priority processes may wait a long time if higher-priority work continues to arrive. Systems can use aging or other policy choices to help prevent starvation.

Compare more than one number

Waiting time records how long a process spends ready without running. Turnaround time covers the time from arrival through completion. CPU utilization describes how much of the simulated interval is spent executing work. Each metric shows a different aspect of a schedule, so comparing them together gives a more balanced view.

I implemented these four algorithms in CPU-SchedSim using C++. The simulator includes context switching, preemption, configurable settings, exponential arrivals, and detailed metrics. Running the same workload through different policies makes the trade-offs visible.
