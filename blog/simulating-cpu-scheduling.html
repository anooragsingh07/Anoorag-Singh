Simulating CPU Scheduling Algorithms with C++

June 10, 2024 · 8 min read

Building CPU-SchedSim turned operating-systems scheduling from a set of textbook rules into something I could observe, compare, and measure.

CPU scheduling is the operating system’s way of deciding which ready process gets time on the processor. That decision changes how long processes wait, when they finish, and how steadily the CPU stays busy. I built CPU-SchedSim to make those trade-offs easier to see in practice.

Four ways to choose the next process

The simulator covers four familiar approaches. First-Come, First-Served (FCFS) runs processes in arrival order. Shortest Job First (SJF) chooses the process with the smallest expected burst. Round-Robin gives each ready process a configurable time slice and cycles through the queue. Priority Scheduling selects according to assigned priority.

These rules produce different schedules even with the same input. A short job can finish quickly under SJF, while a long job may wait. Round-Robin shares processor time more evenly, but its behavior depends on the time quantum. FCFS is simple to follow, though a long process at the front can hold up shorter work behind it.

Representing a workload

To compare algorithms fairly, the simulator needs a set of processes with arrival times, CPU bursts, and any algorithm-specific settings such as priority or time slice. It also models context switches and preemption so a schedule reflects more than just a list of process names.

Configurable values make it possible to adjust the workload and see how the results change. Exponential arrival times help vary the spacing between incoming processes, while detailed metrics make each run easier to compare.

What the metrics make visible

Waiting time measures time spent ready but not running. Turnaround time measures the interval from arrival to completion. CPU utilization describes how much of the simulated time is spent doing process work. Looking at these measures together is more useful than declaring one algorithm the winner: a policy can reduce one metric while making another worse.

The project helped me connect scheduling decisions to system responsiveness. Implementing each policy in C++ also gave me a concrete place to reason about queues, process state, and the points where a preemption changes the schedule.
